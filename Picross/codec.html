How It Works

Serialization (JSON Format)

The input is a JSON object representing a Picross puzzle with only clues, for example:

{
  "topClues": [[2,1], [1,10], [0]],
  "leftClues": [[0], [2], [1,12]]
}

- Each inner array is a clue group (e.g., [2,1] means 2 filled, gap, 1 filled; [0] means no filled cells).
- Numbers range from 0 to 15 (0 means empty row/column, max for a 15x15 grid).
- Grid size: width (topClues length) × height (leftClues length), each ≤ 15, not necessarily square.

Encoding Method (Compressed Format)

The JSON is compressed into a Base64 string using a header and bit-packed data:

Encoding Steps:

1. Header (22 bits):
   - 4 bits: Width (number of topClues groups, 1-15).
   - 4 bits: Height (number of leftClues groups, 1-15).
   - 7 bits: Total number of numbers in topClues (0-127).
   - 7 bits: Total number of numbers in leftClues (0-127).
2. Data:
   - For each number (0-15), encode as 4 bits (0 -> 0000, 15 -> 1111, no subtraction).
   - Append 1-bit marker:
     - 0: Continue in current group.
     - 1: End of group (last number in a row/column clue).
   - Concatenate all numbers from topClues, then leftClues.
3. Combine header and data into a bit stream.
4. Pad with 0s to a multiple of 8 bits (byte boundary).
5. Split into 8-bit bytes, convert to characters, then encode as Base64.

Decoding Steps:

1. Decode Base64 to bytes, then to a bit string.
2. Extract header:
   - First 4 bits: Width (W).
   - Next 4 bits: Height (H).
   - Next 7 bits: Number of numbers in topClues (N1).
   - Next 7 bits: Number of numbers in leftClues (N2).
3. Read data (5-bit chunks):
   - 4 bits: Value (0-15 directly).
   - 1 bit: 0 (add to current group), 1 (end group, add to topClues or leftClues).
   - First N1 numbers go to topClues (W groups), next N2 to leftClues (H groups).
4. Build JSON with topClues and leftClues arrays.

Example: A 5x5 (~15 numbers) compresses to ~12 bytes. A 15x15 with ~40 numbers is ~28 bytes (~38 chars Base64).
